# GridGuide — project overview

**Industry:** Electric utilities (fictional demonstration)  
**Audience:** Residents reporting a power interruption or seeking safety guidance  
**Primary channel:** eGain AI Agent customer self-service  
**Distinctive capability:** impact-aware triage that surfaces immediate safety needs before routine reporting, collects only a broad demo service area and issue category, and directs urgent hazards to local emergency services while presenting clearly fictional, unmonitored contact options for non-urgent follow-up.

## Customer problem

During a power interruption, people often need two things at once: clear, reliable next steps and a quick way to notify the service provider. A generic FAQ bot can answer questions but leave the user to determine the next action or repeat information during a handoff.

## GridGuide experience

GridGuide uses a small set of original, source-linked safety articles. Its eGain Custom API has successfully created persistent fictional reports in the supporting API. Every receipt clearly says the report was stored only in the demo system. The sample status feed is labeled synthetic and is never described as live.

## Value hypothesis

GridGuide aims to reduce effort for routine outage reporting while making safety escalation easy to reach. No measured service outcomes are claimed; any business impact must be validated with a real utility and operational data.

## Current delivery state

The supporting API, local tests, knowledge content, intent/workflow specifications, and submission materials are prepared. GridGuide is configured in eGain, the hosted report API is reachable with persistent storage, and eGain has returned successful demo report receipts. Remaining work is to test unverified behavior cases and the embedded public chat, record the demo video, and complete the hackathon form and eligibility checks.
